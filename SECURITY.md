# Security Policy

## Reportar una vulnerabilidad

No publiques credenciales, datos de usuarios, pasos de explotación ni detalles de una vulnerabilidad sin corregir en un issue público.

La vía preferida es **Report a vulnerability** en la pestaña Security del repositorio, cuando GitHub Private Vulnerability Reporting esté habilitado. Si esa opción no aparece, contacta al mantenedor de forma privada mediante su perfil de GitHub y solicita un canal seguro.

Incluye versión/commit afectado, impacto, pasos mínimos de reproducción y evidencia sin datos personales. No envíes contraseñas, tokens activos, claves de API ni datos de terceros.

## Alcance

Se consideran dentro del alcance el sitio web, módulos JavaScript, futuro BFF, políticas de Supabase/PostgreSQL y flujos de autenticación y guardado.

Las partidas locales son datos controlados por el usuario. No son evidencia confiable de resultados, logros competitivos, monedas o clasificación.
